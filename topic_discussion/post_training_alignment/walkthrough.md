# 后训练与对齐深入阅读

## 主故事线

这条专题最适合按下面这条顺序来读：

`SFT model -> alignment gap -> method choice -> preference data -> evaluation -> project decision`

重点不是记住几个缩写，而是理解：模型从“已经会回答”走向“更符合偏好”时，为什么会出现方法分化，以及这种分化最后怎样反映到项目交付上。

## 1. 从 SFT 之后开始

先立一个前提：

- SFT 解决的是“模型能按样本学会回答”。
- 后训练 / 对齐解决的是“模型回答得是否更符合偏好、更安全、更稳定”。

所以后训练不是训练流程的尾巴，而是目标函数和评测口径发生变化之后的一条新主线。

## 2. 为什么方法会分化

进入 `01` 之后，应该先回答这个问题：

- 如果只靠 SFT，哪里会和真实偏好错位？
- 一旦目标从“模仿回答”变成“偏好更优的回答”，为什么就会出现 RLHF / PPO、DPO、GRPO 这些不同路线？

这一步的目的，是先把“为什么需要后训练”立住，再去看具体方法。

## 3. 看经典但重的路线

进入 `02` 时，重点不是只记 RLHF / PPO 的公式，而是要看：

- rollout 和 reward model 为什么把链路拉长
- 为什么 PPO 常常意味着更高的显存、计算和系统复杂度
- 为什么它仍然是理解后训练全貌的重要基线

## 4. 看更轻的偏好优化

进入 `03` 时，重点是：

- DPO 怎样把偏好优化改写成更直接的目标
- 为什么它更容易和已有 SFT / LoRA 流程接上
- 它对偏好对质量有什么依赖

## 5. 看 group-wise 路线

进入 `04` 时，重点是：

- GRPO 为什么要看候选组而不是单个 chosen / rejected 对
- 它为什么更适合生成式、相对比较式的场景
- 它的问题又常常出在候选构造和评测解释上

## 6. 回到数据和评测

进入 `05` 后，要把注意力放到：

- chosen / rejected 怎么构造
- group candidates 怎么得到
- win-rate、pairwise accuracy、judge score 怎么对应方法目标

很多对齐失败，不是因为 loss 写错，而是因为这一步口径不一致。

## 7. 落到项目决策

最后进入 `06` 时，不要只看 loss 或单一指标。

至少要回答：

- 这个方法和数据形态是否匹配？
- 评测是否真的支持“更对齐”的结论？
- 最终该 adopt、继续 tune，还是 reject？

`84 / 85` 的项目页，就是这一步的项目化落点。

## 典型分支

### 分支 1：SFT 已经跑通，但不知道是否该继续对齐

先看 `01`，再去 `03 / 04`，判断目标是否真的从“模仿”升级成了“偏好优化”。

### 分支 2：方法名很多，不知道怎么选

先看 `02 -> 03 -> 04`，把 PPO、DPO、GRPO 的对象、代价和适用场景分清。

### 分支 3：项目能跑，但结果说不清

先看 `05 -> 06`，确认数据和评测口径是否支撑最终决策。

## 阅读建议

1. 第一次读，按 `01 -> 02 -> 03 -> 04 -> 05 -> 06`。
2. 已经懂方法名但不懂数据和评测，先读 `05`。
3. 已经有项目页，直接读 `06` 再回查 `03 / 04 / 05`。
